# ORK design notes — session of 2026-06-06

Working session focused on prototyping ORK v1 in `experiment.ipynb` and discovering
its limitations. Captures architectural decisions, failures observed, and the
intended v2 direction.

---

## v1 architecture (the starting point)

A knowledge graph where:
- Each node has two learned vectors: `key` and `query` (dim=128).
- Edge A→B is **navigable** iff `dot(K_A, Q_B) > 0`. Soft-gated via sigmoid
  for differentiability: `navigate(a, b) = sigmoid(dot(a, b)) * compose(a, b)`.
- Composition along a chain uses RotatE-style complex rotation: treat the
  dim-vector as dim/2 complex numbers, multiply elementwise.
- The composite is itself K-shaped → protocol closes on itself, supports
  arbitrary chain length.
- **No separate relation embeddings.** Relations emerge from K·Q dot products.

### Why RotatE-style rotation

- Magnitude preservation under composition (so chains don't blow up or collapse).
- Non-commutativity (matters for chaining: `parent_of(mother_of(x))` ≠
  `mother_of(parent_of(x))`).
- Inverses are free (`-θ` for `+θ`).
- Cheap: `dim/2` independent 2D rotations via complex multiply.
- Trade-off: this is a *torus subset* of full SO(N), not the full rotational
  expressivity. RotatE results suggest the restriction is usually not the
  bottleneck; entity embeddings absorb the basis choice.

### Soft vs hard gate

Hard gate (`return zeros if dot <= 0`) is non-differentiable — closed paths get
zero gradient, model can't learn to open them. Soft gate (`sigmoid(dot) *
compose`) keeps gradient flowing. Soft gate doesn't enable "revival via context"
at inference; it's a learnability fix only.

## v1 failure modes discovered

### 1. Tied parameters serve two objectives

K and Q have to simultaneously satisfy:
- **Score**: dot product should be large for valid edges.
- **Compose**: rotate meaningfully when used as a chain operand.

These can pull in conflicting directions. The transformer-style fix would be a
single underlying `e` per node with separate learned projections to K, Q, V.
Tabled for v1.

### 2. Catastrophic forgetting

Online single-shot updates overwrite shared K/Q vectors. Learning a new fact
about "dogs" moves `dogs.key`, which can break earlier facts that depend on it.

### 3. Function-word hubs ("are", "is")

Surface verbs appear in nearly every statement, so their K/Q vectors are pulled
by thousands of disjoint constraints from radically different domains
("dogs are mammals" vs "leaves are green" vs "Paris is in France"). The hub
parameters collapse to a bland midpoint that doesn't do any role well.
Catastrophic forgetting is most acute here. Polysemy is the deeper issue
underneath — same surface form, different semantics, one vector.

### 4. Storage tension

Replay-based mitigation of catastrophic forgetting requires storing all past
statements indefinitely (O(num_statements × avg_length)). This is unbounded
growth — the model is using episodic storage as a crutch for failing to
consolidate information into the weights. Symptom of a deeper modeling problem,
not an acceptable steady state.

## Pivots considered during v1

| Direction                                            | Pro                                                              | Con                                                              |
|------------------------------------------------------|------------------------------------------------------------------|------------------------------------------------------------------|
| Edge-array per node (each edge has its own relation) | No interference; new facts don't overwrite                       | Loses implicit-relation pitch; storage grows; weaker inductive   |
| Ego-graph replay (replay edges touching endpoints)   | Bounded cost (linear in degree); preserves online flavor         | Doesn't fully solve cross-node interference; freezes leak signal |
| Degree-based LR decay (`lr * exp(-degree/τ)`)        | Cheap; concepts crystallize naturally; cognitively plausible     | Early lock-in; no recovery from wrong learning; doesn't fix hubs |
| Crisis mode with iterative deepening                 | Self-scaling response to failure magnitude; localizes blame      | Cost explodes at hubs; oscillation risk; needs anchor selection  |

The order-of-learning being load-bearing is a *bug* if ORK is a knowledge
representation (eval on FB15k-237) and a *feature* if ORK is a cognitive model
(primacy effects, sensitive periods). The pivots above are more defensible under
the cognitive-model framing.

---

## Current v1 direction (combined)

1. **Keep K/Q-per-node** for now. Defer the K/Q/V projection refactor.
2. **Ego-graph replay** on each `learn()`: collect all past statements that
   share a node with the new statement; jointly optimize the directly-named
   parameters against all of them.
3. **Endpoint-only updates** — only nodes directly named in the current
   statement are trainable; passenger nodes are frozen for that call but
   plastic in their own future calls.
4. **Degree-based LR decay** with a skip threshold below which a node is
   treated as "consolidated".
5. **Crisis mode** triggered by high loss on previously-confident statements:
   bump LR, iteratively deepen replay scope (1-hop, 2-hop, ...) until loss
   reconverges, with a depth cap to prevent hub-triggered cascades.

The "trigger for crisis" is the interesting design problem. Candidates:
- Single very-high-loss event (probably too noisy).
- Running average of recent loss above baseline.
- **Loss on previously-confident predictions rising** — most cognitively
  meaningful: "my world model is breaking" vs "this one thing was hard".
- KL divergence between recent loss histogram and long-run baseline.

## v1 evaluation plan (the experiment that makes it notable)

**Link prediction / KG completion** on a toy graph. This is THE standard test
for KGE systems.

Concrete setup:
- Train on: "Dogs are mammals", "Cats are mammals", "Snakes are reptiles",
  "Mammals produce milk", "Dogs are reptiles" (False), "Cats are reptiles"
  (False).
- Test (no further training): score "Cats produce milk" (should be high),
  "Snakes produce milk" (low), "Dogs produce milk" (high), "Mammals are
  reptiles" (low).

If the toy can do this, ORK v1 has demonstrated:
1. K/Q embeddings learned compositional structure rather than memorizing.
2. The rotation operator generalizes — composing learned rotations produces
   meaningful outputs on unseen pairs.
3. Catastrophic forgetting hasn't destroyed the learned chains.

Caveats to be honest about:
- 6 training statements and ~10 vocabulary items is barely distinguishable
  from random alignment in 128-D space. Defensible claims need many seeds and
  many toy graphs, or a scale-up to ~50-node WordNet fragment.
- Current architecture trains gate scores per step but the rotation operator
  only gets gradient through multi-hop chains. The chain length in the toy may
  not give it enough signal.
- Watch for the "produce" hub overgeneralizing: false-but-related statements
  scoring high because the architecture leans on hub vectors.

## v2 direction: manifolds over dynamic neuron fields

### The pivot

v1's one-vector-per-word abstraction is the wrong granularity. It's the source
of the storage tension (replay-as-crutch) and the catastrophic forgetting at
hub nodes. Brains don't have a "dog" neuron — they have populations whose joint
activation pattern encodes dog-ness. The graph is still fundamental — but at
the cell level, not the concept level.

### Core shift

- Concepts become **manifolds** (regions/distributions in activation space),
  not single nodes.
- The graph stays fundamental, but nodes are finer-grained (memory traces,
  features, or sub-units), not words.
- Concept identity emerges from population activation patterns.
- "Dog-ness" can drift, expand, or split as new evidence arrives by reshaping
  the manifold or growing the graph.
- New edges (and new nodes) form when the system detects a lack of expressivity
  — structural plasticity, not just parameter plasticity.

### Prior art to lean on

- **Sparse Distributed Memory** (Kanerva 1988) — patterns stored across many
  cells; retrieval by pattern completion.
- **Modern Hopfield networks** (Ramsauer et al. 2020) — unbounded pattern
  storage with attention-based retrieval; the storage *is* the model.
- **Growing Neural Gas** (Fritzke 1995) — adds nodes when local representation
  error is consistently high. Direct precedent for "grow capacity where the
  manifold can't yet express what it needs to."
- **Dynamically Expandable Networks** (Yoon et al. 2018) — continual learning
  with capacity expansion on demand.
- **Adaptive Resonance Theory** (Grossberg) — explicit novelty detection that
  allocates new units.
- **Sparse distributed representations** (Hinton 1981 onward) — the underlying
  argument that concepts are population codes.

### Why this resolves v1's tensions

- **Storage growth** is no longer a crutch — explicit memory of episodes is
  the *point*, matching episodic-memory structure in cognition.
- **Catastrophic forgetting at hubs** dissolves because no single node is
  responsible for a whole concept; perturbations get absorbed across the
  population.
- **Polysemy** is handled because each instance contributes a different trace
  to a context-dependent manifold; retrieval picks the right population per
  context.
- **Order-of-learning effects** can be preserved — early traces shape initial
  geometry, later traces incrementally adjust. Desirable for a cognitive model.

### Design surface still to figure out

1. **What is a node?** Memory trace? Feature? Sub-symbol? Choice has to come
   first — everything else depends on it.
2. **Composition over populations.** What does "rotate dogs by are" mean when
   both are clusters? Candidates: sample-and-rotate, attention-weighted-mean
   then rotate, or trace-by-trace rotation with re-aggregation.
3. **The growth trigger.** When does the graph add a node or edge? Candidates:
   local prediction error, representation collisions, sustained loss on
   previously-confident regions.
4. **What grows.** Adding edges (new associations) is the cheaper, more
   frequent move; adding nodes is the bigger event. Both probably needed.
5. **Retrieval efficiency.** Without entity slots, every query is a
   nearest-neighbor search over the trace store. ANN indexes are standard
   but another moving part.

### Unresolved blockers before v2 is buildable

- No concrete experimental hypothesis. v1 has one (link prediction on a toy);
  v2 does not yet.
- Need targeted reading first — at minimum Modern Hopfield (Ramsauer 2020),
  Growing Neural Gas (Fritzke 1995), and a continual-learning survey.
- "What does a single training step look like" is fuzzy.

## Sparse network + Hebbian as substrate

Continuing v2 design: the substrate is converging on **a very sparse network
with Hebbian (or STDP) learning**. Concepts are activation patterns over a
small subset of cells (~2-5% active at any moment, matching cortical sparsity).
Edges strengthen between co-active cells. No global loss, no backprop.

### Why Hebbian / not gradient descent

- Local rules are biologically plausible and cheaper.
- New facts don't have to propagate gradients through the whole network — they
  just strengthen the specific edges between co-active cells.
- No catastrophic forgetting at the parameter level because no single edge
  encodes a whole concept.

### What Hebbian + sparse does NOT give you out of the box

- **Composition / multi-step reasoning.** Hebbian learns co-occurrence;
  it doesn't learn "A is B, B is C, therefore A is C." Multi-step inference
  needs an additional mechanism layered on top.
- **Relation typing.** "X and Y are associated" but in what way? Is-a vs has-a
  vs causes vs precedes — Hebbian doesn't distinguish.
- **Negation.** "Dogs are not reptiles" has no clean Hebbian encoding.
- **Quantification.** "All" vs "some" can't easily live in association
  strengths.
- **Directionality.** Plain Hebbian is symmetric; STDP fixes this partially.

So the substrate is well-precedented but **the composition layer is the
research problem.** Candidates for the composition layer:

- **Attention over patterns** (modern Hopfield) — composition becomes
  attention-weighted retrieval; given a query, retrieve relevant traces,
  combine their activations.
- **Tensor product representations** (Smolensky) — explicit role-filler
  binding into composite sparse patterns.
- **Hierarchical predictive coding** — higher layers predict lower; inference
  emerges from the prediction stack.
- **Sequential activation chains** with STDP-style temporal binding.

## Geometric framing: "are" as overlap

A separate thread that turned out to converge with the same direction.

### The intuition

Concepts are *manifolds* (regions/distributions in activation space).
"Dogness" is a manifold, "reptileness" is another. "Are" is the overlap
between them. Truth becomes a topological property — IS-A means the
subregion containment holds.

### Prior art — this is well-trodden ground

- **Box embeddings** (Vilnis et al. 2018) — entities are axis-aligned
  hyperrectangles; IS-A is literal geometric containment (A ⊆ B).
- **Poincaré / hyperbolic embeddings** (Nickel & Kiela 2017) — hyperbolic
  geometry naturally encodes tree-like hierarchies; descents follow the
  geometry.
- **Cone embeddings** — entities as cones; IS-A as cone containment.
- **Gaussian / probabilistic embeddings** (Vilnis & McCallum 2014) — entities
  as densities, KL divergence as containment measure.

### Why this is appealing for ORK

- **Compositionality emerges from geometry.** If A ⊆ B and B ⊆ C, then
  A ⊆ C transitively. No learned rotation operator needed for this case —
  topology does the work.
- **Polysemy of "are" dissolves.** "Are" isn't an entity being scored; it's
  the test (the overlap operation). No embedding required for it.
- **Catastrophic forgetting reduces.** Adjusting the dogness manifold's
  overlap with mammalness doesn't perturb cats's overlap with mammalness —
  they're separate regions.

### The honest catch — "are = overlap" only works for IS-A

- "Dogs HAVE four legs" — possessive, not containment.
- "Dogs CHASE cats" — verb, directed action between regions.
- "Dogs are FROM Asia" — origin/location.

You'd either restrict to is-a-style relations (most KGE benchmarks are
heavily is-a-weighted; defensible), have multiple geometric operations per
relation type (clean but loses elegance), or find a more general framework
where all relations live (open research).

## Primitive vs compositional relations

A philosophical commitment that informs the v2 design:

- **"Are-ness" is experiential and fundamental.** Some relations are primitive
  — they correspond to basic ways the world presents itself in experience.
  Set membership, containment, identity, presence. Possibly innate, possibly
  developmental, but not decomposable.
- **"Chase-ness" is compositional and learned.** Complex relations are built
  from primitives plus experience. "Chase" = violentness + naturalness +
  directed-motion + intent. Decomposable, varies across instances.

This matters for v2 because it suggests:
- Primitive relations get hardcoded or specially-structured geometric
  operations (overlap, containment, presence).
- Compositional relations emerge through learning over the primitive
  substrate.
- The architecture should distinguish these — they shouldn't both be modeled
  the same way.

## Truth as felt recognition

The deepest reframing of the session, with significant cognitive-science
backing.

### The claim

Truth-judgment isn't a derivation. It's a *retrieval signal*. When you
encounter "dogs chase cats", you don't run an inference; you feel a set of
memories light up. The configuration is recognized as congruent with stored
experience. "Cats chase cars" doesn't fail an inference — it just doesn't
*light anything up*. Falsity is silence, not a low score.

"Cats chase dogs" is felt as humorous because it settles to an attractor —
but a *different* one than expected. Humor as the cognitive marker of
"your prediction was disrupted by an alternate valid retrieval."
Incongruity-resolution theories of humor (Kant onward) treat this as the
core mechanism.

### Prior art

- **Exemplar theory** (Medin & Schaffer 1978, Nosofsky 1986) — concepts are
  stored as collections of past instances; new stimuli are judged by
  similarity to the stored set. No abstract prototype required.
- **Embodied cognition** (Barsalou, Lakoff) — meaning is grounded in
  sensorimotor experience, not abstract symbol manipulation.
- **Hopfield-style recognition** — settling into a stored attractor *is* the
  act of recognition; there's no separate "is this true" computation.
- **Predictive coding / free energy minimization** (Friston) — surprise is
  the signal; minimizing it across time is the learning dynamic.

### Implications for ORK

- Truth becomes **retrieval strength**, not gate-and-compose chain score.
- Negatives are configurations memory doesn't have a strong response to.
  You don't need to *train* on negatives — silence is the negative signal.
- Composition emerges from retrieving multiple traces and combining their
  activations.
- Polysemy is automatic: "are" doesn't need an embedding because it's part
  of the query pattern that gets retrieved against, not a thing being scored.

### The honest catch

- **Pure recognition can't judge truly novel patterns.** If truth is "do my
  memories resonate", how do you judge a sentence you've never encountered?
  Humans do it via similarity-based extension plus compositional machinery.
  That extension *is* the hard part.
- **You need a similarity / partial-match mechanism.** Nosofsky's Generalized
  Context Model formalizes this with attention-weighted similarity. Modern
  Hopfield networks do it with attention-based pattern retrieval.

## The synthesis: K/Q survive, but they're attached to memories not entities

The closing realization that loops v3 back to v1 but reinterprets it.

### What changed

v1 attached K and Q to **entities** (one pair per word/node). The K/Q
mechanism then had to compress everything about an entity into two vectors
— which is where catastrophic forgetting and hub problems came from.

v3's reinterpretation: K and Q are the **retrieval mechanism** over a store
of memory traces. Each trace has its own K (its address, what it's about)
and is retrieved by Q (the query). This is **content-addressable memory**
— exactly what transformer attention and modern Hopfield networks do.

### The reframing in table form

| Aspect          | v1 (entity-as-embedding)                | v3 (memory retrieval with K/Q)              |
|-----------------|------------------------------------------|---------------------------------------------|
| What has K/Q    | Each entity/word                         | Each stored memory trace                    |
| Number of K/Q   | One per entity                           | Grows with experience                       |
| What K/Q means  | Compresses everything about the entity   | Address for retrieving this specific memory |
| Truth judgment  | Gate-and-compose chain score             | Strength of retrieval activation            |
| Forgetting      | High (shared params overwritten)         | Low (new memories add new traces)           |
| Storage         | O(num_entities)                          | O(num_memories) — unbounded, cognitively right |

### Selectivity of retrieval

When recalling a cat chasing a dog, you don't retrieve everything you know
about cats. Retrieval is selective — cued by the query, scoped by the
context. This selectivity is exactly the **softmax over K·Q similarities**:
high-relevance traces dominate; low-relevance ones contribute negligibly.

### Depth of retrieval scales with disruption

- Routine query → narrow retrieval (top-k similar traces) → standard
  inference.
- Major surprise → broad retrieval ("rethink everything about cats") →
  many traces activate, including dissimilar ones → forced reconciliation.

In attention terms, this is **temperature scaling on the softmax**:
- Low temperature → sharp distribution → narrow retrieval → routine
  recognition.
- High temperature → flat distribution → broad retrieval → broad
  reconsideration.

The trigger for raising temperature is the same as the crisis-mode trigger
we sketched earlier: prediction error on previously-confident retrievals.
Surprise widens the search.

### v2 architecture, as currently committed

Combining all the threads above:

- **Substrate**: sparse network of memory traces. Each trace is a sparse
  activation pattern over an underlying field of cells.
- **Storage**: Hebbian-style strengthening between co-active cells when a
  trace forms.
- **Retrieval**: each trace has a K; queries Q score against all K's;
  softmax-attention pulls back the top-relevance traces.
- **Composition**: retrieved traces combine to form the judgment, possibly
  via rotation (v1's compose operator survives, applied at trace-level
  retrieval results) or via pure attention pooling.
- **Truth**: retrieval strength. Configurations that produce strong, coherent
  retrievals are "felt as true." Silence is falsity.
- **Crisis / surprise**: prediction-vs-retrieval error raises retrieval
  temperature, broadens the search, allows manifold reshaping.
- **Geometric scaffold**: "are" / containment relations as primitive
  topological operations; learned compositional relations layered above.

This isn't a finished blueprint, but it's a coherent commitment. None of the
pieces are research-novel individually; the combination is the contribution.

### What this implies for v1

v1's K/Q machinery survives in v3 — repurposed but mechanically similar.
That means time spent on v1's compose/navigate/training mechanics isn't
wasted. Operators carry over; what changes is what they're attached to and
how the inference is framed.

## v1 training loop, debugging, and what it revealed

After wiring up `learn()` with ego-graph replay, the training loop ran
end-to-end and produced loss curves. Reading the curves revealed a real
architectural problem — and pushed the design forward.

### The observed behavior

- **Chains with new vocabulary converge fast.** "Dogs are mammals" (T) drove
  loss to ~1e-9 in a few dozen Adam steps. "Mammals produce milk" (T) did the
  same.
- **Chains that share edges with prior chains plateau or oscillate.** "Dogs
  are reptiles" (F) oscillated 0.4–5 indefinitely. "Snakes are reptiles" (T)
  same pattern. Loss never approaches zero.

### Diagnosis: per-gate labeling creates impossible constraints

The training loop labeled every gate in a chain with the chain's overall
label. So:

- "Dogs are mammals" (T) → both gates (`dogs→are`, `composite→mammals`) get
  label 1.
- "Dogs are reptiles" (F) → both gates (`dogs→are`, `composite→reptiles`) get
  label 0.

Both chains share the first gate (`dogs→are`). It's being asked to be
simultaneously 1 (from the mammals chain) and 0 (from the reptiles chain).
The optimizer compromises at the log-odds of the label distribution and the
loss can't go to zero.

This is the *same* catastrophic-interference flavor we hit earlier, now
showing up as a labeling problem rather than a parameter-sharing problem.

### The conceptual fix: "dogs are" is unresolved

The deeper insight: "dogs are" alone isn't true or false. It's a **prefix —
a superposition of possible completions**. Truth doesn't materialize until
the chain terminates. Asking the intermediate gate `dogs→are` to take a
truth value is asking the wrong question.

The intermediate composite encodes "where can we go from here" — a
distribution over viable continuations. Truth is a property of the *complete
chain*, not of any prefix.

### Chain-level scoring as the architectural fix

Instead of labeling each gate, **sum the gate logits across the chain and
label the sum**. One score, one label, per complete chain.

```
score("dogs are mammals") = logit(dogs→are) + logit(composite→mammals)
score("dogs are reptiles") = logit(dogs→are) + logit(composite→reptiles)
```

Now the optimizer is free to put the truth-determining signal wherever it
needs to be. Shared prefixes share their early logit; divergent completions
diverge at the final gates. The truth differentiation lives at the
*disambiguating word*, not at the shared prefix — which is conceptually
correct.

### Soft truth values and context-dependent truth

This framing handles graded / context-dependent truth naturally.

- "Dogs are wet" → 2 gates summed, somewhat low score → soft-false.
- "Dogs are wet when they swim" → 5 gates summed, the additional rotations
  redirect the composite into truth-territory → true.

The shared prefix `dogs are wet` doesn't need a single fixed truth value.
Its contribution to the sum is fixed; later gates can pull the total either
direction. Context naturally reverses truth via composition.

This also matches the **degree-of-truthiness** intuition: train labels are
binary, but the model's output is graded. A prefix that appears in 5 true
chains and 2 false ones converges to a logit reflecting that distribution
— which is the right behavior, not a bug.

### Implicit re-discovery of standard KGE structure

Chain-level scoring is **a sequential generalization of standard
holistic-triple KGE.** Standard KGE scores `(h, r, t)` as one number, one
label. Chain-level ORK scores chains of arbitrary length as one number, one
label. A triple is just a chain of length 3.

What ORK adds over standard KGE:

1. **Arbitrary chain length** — natively expresses "dogs are wet when they
   swim" without compressing it into a single relation.
2. **No separate relation embeddings** — "are" is a node with K/Q like any
   other; entities and relations share a unified vector space.
3. **First-class intermediate composites** — the vector after "dogs are" is
   queryable in its own right.

What ORK loses:

1. **Relation identity** — no named relations, only emergent rotations.
   Recovering relation semantics requires post-hoc clustering.
2. **Cheap scoring** — N rotations vs one operation. More expressive ↔ more
   parameters ↔ more data needed.
3. **Direct benchmark applicability** — FB15k-237 and friends are flat
   triple datasets. ORK's length-generality doesn't show up there. To
   demonstrate it, you'd need multi-hop or NL datasets.

### Status of v1 implementation (end of session)

- `compose` + `navigate` (soft-gated) working.
- `learn()` with ego-graph replay running end-to-end on toy statements.
- Per-gate labeling identified as architecturally wrong (the contradictions
  it creates produce the observed plateaus).
- **Not yet implemented but next step**: chain-level scoring (sum logits per
  chain, one label per chain) as the principled replacement.
- Bugs along the way:
  - Labels need to be `{0, 1}`, not `{-1, 1}`.
  - `range(2, metadata["index"])` was off-by-one — should be
    `+ 1`.
  - Forward pass must be inside the optimizer loop to avoid
    "backward through freed graph" errors. Single-step training doesn't
    converge; ~50 iterations needed.

## v1 as a defensible contribution if it works

Reflecting on the design space: **chain-level scoring + RotatE-style
sequential rotation + unified entity/relation vector space + arbitrary
chain length** is, taken together, a novel combination. Not all of the
pieces are individually new (RotatE has rotations; Path-RNN composes over
paths; some recent work explores unified embeddings), but the specific
synthesis is.

To make it count as a contribution at a venue:

1. **Empirical wins on a standard benchmark.** Match or beat TransE / RotatE
   / ComplEx on link prediction (FB15k-237 or WN18RR). Even a competitive
   showing establishes the baseline result.
2. **An ablation that isolates which component matters.** Chain-length?
   Unified space? Sequential rotation? Each should be shown to contribute.
3. **A demonstration of the length-generality.** A toy where the model
   handles "dogs are wet when they swim" → True after being trained on
   "dogs are wet" → False. This is the kind of "context reverses truth"
   result that a fixed-arity model cannot reproduce.

What would limit it:

- Catastrophic forgetting at scale. v1's known issues (hub thrashing,
  replay-buffer growth) will become obvious as the graph gets bigger.
- Prior art. Path-RNN (Neelakantan 2015) and ChainsofReasoning do
  compositional path reasoning; reviewers may point at these.
- The unified-vector-space claim might not buy measurable performance over
  having separate relation embeddings.

**The user's stated goal:** this work is primarily for *learning*, not
necessarily for publication. Even useless-but-novel is acceptable. The
novelty bar (for the combination) is met; the value bar requires
experimental work.

## Honest read at end of session

v1 has now run end-to-end on a toy. The training works mechanically; the
loss curves are interpretable; the bugs that surfaced (per-gate labeling
creating contradictions) led to a principled architectural reframing (truth
lives at the chain, not at the edge).

The next concrete step is small but important: **switch from per-gate
labeling to chain-level scoring**. This should resolve the plateaus and
make the toy actually converge to a coherent solution.

After that, run the small link-prediction experiment to see if held-out
chains score correctly. That's the test that turns v1 from "interesting
exploration" into "has it learned anything."

v2's manifold/retrieval direction remains the longer-term aim, but v1 is
now mature enough to actually produce a result before the pivot. That's a
better place to be than where we started.
